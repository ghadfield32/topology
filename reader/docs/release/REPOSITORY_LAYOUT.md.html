Repository layout: who owns what

The repository holds six kinds of thing. They look similar on disk and have completely different owners, which is the main source of confusion. This file defines every path once.

The four ownership rules

  1. Lesson order lives in curriculum/catalog.json and nowhere else.
  2. Native experiment definitions live in native/protocols/labs.json and nowhere else. workbooks/polyglot contains no catalogue of its own.
  3. Generated notebooks are never hand-edited. Change tools/build_language_notebooks.py, regenerate, then run --check. It refuses unregistered files on purpose, so a hand-added README would fail it.
  4. Your work goes in my_work/. Never edit a reference answer or the shared native/go/ / native/rust/ source to complete an assignment.
  5. Engineering-unit order lives in systems/catalog.json and nowhere else. A project check compiles your private my_work/ copy, not the reference source, so editing and breaking it is the exercise.

The distinction people get wrong

Path Role
native/go/, native/rust/ the reference. Committed, shared, read-only. Every lab uses it.
my_work/<session>/native/go/, .../rust/ your copy, created by native_course.py prepare. Edit here, then go test / cargo test in that copy.

notebooks/ is the original course and has no go or rust folder. The 171 language notebooks are under workbooks/polyglot/.

uv run --no-sync python tools/check_matrix.py --list
uv run --no-sync python tools/check_matrix.py --fast

What a link in a notebook means

The notebooks sit three levels deep, so their links are root-anchored. Each notebook opens with a "Where every path points" legend that defines the vocabulary. A bare `lessons/01_lesson.md` in prose is a label; the legend says where it actually is. Every clickable link resolves from the notebook's own folder — a test enforces that.
