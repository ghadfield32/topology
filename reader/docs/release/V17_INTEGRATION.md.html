A real portability fix (our change, not the archive's)

The archive's systems/python/workflow.py:command() ran tsc by bare name. On Windows a package-manager install is a .cmd shim that CreateProcess cannot locate, so the integrated demonstration failed with [WinError 2] The system cannot find the file specified. command() now resolves the executable (including a .cmd/.bat shim through %COMSPEC%) to an absolute, shell-free argv. Regression tests were added in systems/tests/test_workflow.py. The same latent problem existed for any npm/global shim; it is fixed centrally rather than per call site.

Two imported v13 tests created symlinks unconditionally and failed on a Windows host that disallows symlink creation (as the repository's own tests already handled). Both now skip with an explicit Host disallows symlinks reason, so the check still runs on hosts that permit symlinks.
