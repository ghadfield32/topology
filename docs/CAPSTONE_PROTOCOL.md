# Independent capstone protocol

The digits capstone is a complete worked example. After studying its outputs, it is no longer your independent discovery task. Use this protocol for a new question and retain negative results.

## 1. State a testable question

Name the target, observation unit and intended deployment population. “Find interesting topology” is not yet an evaluation question. A possible sports question is whether topological summaries of calibrated motion windows add information beyond declared kinematic features for a specifically labeled task. This is a proposal, not an established benefit.

## 2. Establish evidence and provenance

Record where observations came from, usage rights, collection date, participant/session IDs, sample rate or spatial units, transformations, missingness, selection rules and ground-truth availability. Do not substitute a camera-model prediction for measured truth without labeling it. Do not use ground-plane geometry for airborne positions without valid additional geometry.

## 3. Choose representations before looking at the final test

Specify one point or cell, the metric, scaling, complex construction, filtration parameter and units, coefficient field, dimensions, cutoff, essential-bar policy and feature vector. Give one exact control with a known answer and one deliberately adverse example. Specify why competing simpler choices are plausible.

## 4. Match the split to the scientific unit

Keep dependent observations grouped. Hold out athletes for an unseen-athlete claim; keep sessions separate for a session-transfer claim; use chronological cuts when future deployment is the target. Build overlapping windows within partitions and label feature availability by the last required sample. Fit data-dependent transformations only on training subsets.

## 5. Freeze evaluation

Declare primary and secondary metrics, baseline methods, candidate hyperparameters and selection rules. Save split IDs, data hashes and a machine-readable configuration. Choose on validation; run the final holdout once for the finalized comparison. Record any earlier exposure, including visualization and iterative feature design.

## 6. Run mathematical and software checks

Validate input contracts, boundary-of-boundary, known complexes, dimension sufficiency, invariances, scale conventions and at least one independent computational comparison. Complete Ripser/GUDHI checks locally where those libraries are used. A library skip is a remaining validation item.

## 7. Analyze sensitivity and failure modes

Perturb calibrated units, sampling density, missingness or noise in scientifically justified ways. Report actual perturbation sizes and what is held fixed. Do not equate deterministic stability with significance. Choose resampling units and null models explicitly before making statistical claims.

## 8. Write the report

Include the question, data card, preprocessing diagram, mathematical construction, exact controls, benchmark table with all baselines, per-group errors, sensitivity results, reproducibility instructions and limitations. End with what the evidence supports and what would change your conclusion. No positive TDA result is required for a successful capstone.

## Assessment rubric (proposal, not accreditation)

- Mathematical correctness and explicit hypotheses: 25 points.
- Reproducibility, provenance and tests: 25 points.
- Evaluation design and leakage prevention: 25 points.
- Interpretation, limitations and oral defense: 25 points.

Suggested pass: at least 85/100, no unresolved critical errors, and a delayed explanation without copying the report. Critical errors include using future information, unsupported metric units, missing cofaces, wrong coefficient arithmetic, a false library pass, or claiming significance from lifetime alone.
