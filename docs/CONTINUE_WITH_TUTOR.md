# Continue this course in chat

Use the course as a source of specific learning evidence, not an invitation to rebuild another roadmap.

## First session

“Teach me Stage 00 from this learning package as a complete beginner. Start with observation, feature, label and array shape. Ask me to predict one code result, wait for my answer, then explain it and give me one new example. Do not assume that running the notebook means I understand it.”

## Each later session

“Continue Stage NN, section TITLE. Here are my answers and the notebook output. Separate what I solved independently from what I copied or needed help with. Check definitions and assumptions, explain the first misunderstanding, and give a new small example before moving on. Do not mark the stage mastered until I pass its exercises and a delayed check.”

Include your current stage, the exercise IDs, your actual reasoning, notebook result or complete traceback, and what you believe the result means. For a bug, attach the relevant code and exact environment rather than only describing it as broken.

## End-of-session handoff

Record the last completed section, independently solved exercises, corrected misconceptions, code checks, pending proofs, optional-library status, next precise task and review date. Preserve changed experiment parameters and holdout exposure. Keep learner mastery separate from the package's build verification.

## Efficient learning rule

Spend explanation effort on the earliest missing dependency. An unclear kernel/image definition can block homology; a missing homology definition can block persistence. Do not skip the dependency with an opaque library call. Once a concept is secure, progress without repeating all prior material.
